# dsh-agy-mode

给 DSH（DeepSeek Harness）加一个 **Antigravity 规划模式**：判断交给本机 **Antigravity CLI（`agy`）**，干活交给 **DSH**。开工前由你选两边的模型和思考强度，子任务开不开、同时几个、递归几层也由你定。

继承「标准模式」的全部工具，额外加三样：

| 工具 | 作用 |
|---|---|
| `agy_consult` | 让 `agy` 只读地跑一轮：`mode: plan` 出实现方案，`mode: review` 挑毛病。可指定模型与思考强度。 |
| `agy_models` | 列出本机 `agy` 认的模型 id 与思考强度档位。 |
| `agy_delegation_budget` | 记录你关于子任务的决定：开不开、同时几个、递归几层。**记录之前，`subagent` / `subagent_fork` / `workflow` 一律被拦下。** |

```
┌─ 你 ──────────────────────────────────────────────┐
│ 1. agy 用哪个模型、多高的强度？                     │
│ 2. dsh 自己用哪个模型、多高的强度？                 │
│ 3. 子任务开不开？同时几个？递归几层？               │
└───────────────┬───────────────────────────────────┘
                ▼
        agy 规划（只读）──► dsh 实现 ──► agy 审核 ──► 汇报
```

## 它和其它模式的区别

| | 标准模式 | 本模式 |
|---|---|---|
| 谁做技术判断 | DSH 自己 | `agy`（本机 Antigravity CLI） |
| 谁动文件、跑命令、跑测试 | DSH | DSH（不变） |
| 开工前是否先问模型/强度 | 否 | 是，两边都问 |
| 子任务预算 | 宿主设置（`subagent.maxDepth`） | 你在会话里当场定，且有硬拦截 |

`agy` 始终以自己的 **只读 plan 模式** 运行（`--mode plan`，即使给了 `--dangerously-skip-permissions` 也写不了文件 —— 本机实测确认）。所以「规划」「审核」是它唯一能做的事。

## 安装

需要本机已装好并登录 `agy`（`agy --version` 有输出、`agy models` 能列模型）。

```bash
# 从 GitHub 安装
dsh plugin --profile <你的 profile> add github:fuyu1993/dsh-agy-mode

# 或克隆后本地安装
git clone https://github.com/fuyu1993/dsh-agy-mode.git
dsh plugin --profile <profile> add /绝对路径/dsh-agy-mode
```

装好后重启一次 DSH，新建任务时在模式选择器里选 **Antigravity planner**。

## 配置

`cordis.patch.yml` 里 `agy-planner` 那一行：

| 字段 | 默认 | 含义 |
|---|---|---|
| `command` | `agy` | 可执行文件。裸名走 PATH，绝对路径会被校验。 |
| `timeoutSeconds` | `900` | 单次咨询的 `--print-timeout`。0 表示不设限。 |
| `defaultModel` | `gemini-4-hydrogen-high` | 调用没指定模型时用哪个。 |
| `defaultEffort` | `high` | 调用没指定强度时用哪个；可选 `low`/`medium`/`high`/`xhigh`/`max`。 |

默认值只影响「没指定时」和「问的时候的推荐项」，模式本身仍会在开工前问你。

## 开工前的四个问题

第一次真正动手之前，模式要求 DSH 用 `ask_user_question` 一次问完：

1. **agy** 的模型与思考强度（先用 `agy_models` 拉清单）；
2. **DSH 自己**的模型与思考强度（输入框旁边的模型控件随时也能换）；
3. 子任务：开不开、同时几个、递归几层；
4. 还有哪些信息光靠读代码拿不到。

第 3 条由 `agy_delegation_budget` 落账，之后每次派活都按**当前存活子任务数**和**调用者深度**实时校验 —— 不是靠模型自觉记。没问过就派活，会被直接拒绝并提示先问你。

## 工作流程

1. 用 DSH 的只读工具把事实摸清；
2. 给 `agy_consult` 一份自包含的简报（目标、相关路径、约束、验收标准），拿回方案；
3. 用 DSH 自己的工具实现，按项目既有方式验证；
4. 汇报之前，把 diff 和验证结果用 `mode: review` 发回 `agy` —— 它挑出的问题要么改掉，要么说明为什么不该改；
5. 如实汇报，包括没解决的异议。

`/plan` 计划模式照旧，只是计划本身来自 `agy_consult`。

## 边界与限制

- `agy` **看不到这个对话**，所以提示词必须自包含；模糊的简报只会换来模糊的方案。
- 没登录时 `agy` 的报错只出现在 stderr，插件会把它翻译成「请先登录」而不是回一个空答案。
- 子任务预算按任务记在内存里，**不落盘**：新任务会重新问，这是有意为之。
- 本模式不改变 profile 的权限策略；沙箱与审批设置仍然决定 DSH 自己能做什么。
- 每次咨询受 `timeoutSeconds` 与一小时工具超时双重限制。
